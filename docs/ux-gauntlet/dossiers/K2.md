## Read this first, and do not re-derive it

`docs/audits/kai-mentions-and-coverage-2026-08-07.md`, Part four. It is the
design. It was written from the two reference products' own binaries and recorded
sessions, and its findings are measurements rather than impressions:

- Claude Code ships TWO file-reference shapes and both are live.
- Codex's structured mention path is exercised **zero times in 10,952 turns**.
- The Codex binary confirms files are never read, by the absence of the machinery.

**The second of those is the most important sentence in the document.** A mention
system that is the ONLY way to refer to something will not be used. So the
free-text path keeps working exactly as it does today, and the mention is an
accelerator and a disambiguator, never a gate. Nothing in this wave removes a way
of asking.

No screenshots. Taking one required opening an interactive session of another

**What that leaves open:** the exact popup geometry, its position relative to the

## Job stories and their done conditions

**K2-a. `@` opens a picker that narrows as you type.**
Done when typing `@` in the composer opens a floating panel, typing narrows it,
Enter accepts, Escape closes, and the free-text path is untouched by all of it.

**K2-b. A kind is recognisable before it is read.**
Done when every row carries one glyph per KIND, and where a kind has a rail
destination the glyph is that rail item's own glyph from `shell/nav.js`.

**K2-c. A container can be entered.**
Done when the leading-edge arrow on a container row descends into its children,
the trailing edge ascends, the header is a breadcrumb, and Enter accepts at any
depth. **Leading edge resolves from `documentDirection(locale)`: in Hebrew it is
ArrowLeft.** Both reference products declined to build this, and the audit says
why they could afford to and this product cannot: a spot has no name.

**K2-d. The boundary holds inside the picker.**
Done when a rival channel's name typed into the search returns the SAME "no
matches" a typo returns. Not "none on your channel", which confirms the name
exists.

## Trade facts that bind this piece

**THE COMPETITOR BOUNDARY, and here it has three named rules rather than one.**

1. The cap is applied AFTER scoping. An `omitted` count computed before scoping
   is itself a rival count.
2. No-match and not-ours are indistinguishable.
3. No kind is searchable whose store cannot be channel-scoped.

The pod is safe by construction: the traffic file has no channel column at all,
and the channel shown beside a pod is the operator's own from settings.

**Hebrew, and this is the requirement neither reference product has.** Strip the
one-letter prefixes `ובלמהשכ` on both sides or `בחדשות` never matches `חדשות`.
**Reuse `assistant_context._strip_hebrew_prefixes`. Do not write a second one.**

**Words are read, never invented.** Hebrew labels come from the existing words
modules: `pacing_alerts_api_words.py`, `campaigns_api_words.py`,
`makegood_store_words.py`, `vocabulary.js`, and prompt rule 24. A kind with no
approved word does not ship until it has one. `ברייק זהב`, not `ברייק זהוב`.

`@` is Shift+2 on the Hebrew layout, the same key as English, so no layout
switch. One sigil only: this product has ONE namespace of business objects, and a
second sigil costs a thing to teach traffic operators and buys nothing.

## Reference product, and what to compare

Two, and the audit read both from their own binaries and recorded sessions rather
than from marketing.

**Claude Code.** Compare its two live file-reference shapes, and the fact that it
gives bash-path completion the chaining it WITHHOLDS from `@`. That asymmetry is
the argument for building drill-down here.

**Codex.** Compare its matcher, which this design takes the shape of: kind rank
first, then case-insensitive subsequence over label and id with a prefix bonus,
about twenty lines. Compare its caps: 20 fetched, 8 shown.

**And compare what BOTH declined.** Claude Code kills drill-down with a trailing
space; Codex collapses Directory into File. Both can afford to because a flat
fuzzy search substitutes for navigation WHEN EVERY LEAF HAS A UNIQUE TYPEABLE
PATH. A spot has no name, so this product must build what both declined.

Do not compare icons: both ship none, deliberately, because they have one kind of
thing with a path that already discloses its type. This product has heterogeneous
business objects, which is why it needs them.

`test:direction` matters more here than anywhere: a picker is a portalled overlay,
and the primitive's own documentation warns that a portalled element lands outside
the shell's subtree and resolves its direction against the DOCUMENT. The document
now ships `lang="he" dir="rtl"`, which is why that was fixed first.

The interpreter is `~/.venvs/meridian/bin/python` and no other. The server starts
from the repository root only.
