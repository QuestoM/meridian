# P7 contract: the model console

The section 8.8 publication for P7: the endpoints it owns, the payload shapes it
emits, the files from section 8.2 it wrote, and the helper modules it created.
Published on delivery of round 1 and **re-measured against the shipped tree on
delivery of round 4**, because a boundary sweep and the wave-close gate read
this file as the frozen public surface, and a stale number here reads as a
breach of the product's hardest law.

Round 3 published section 3 under a header saying every number in it had been
taken again, and twelve of them were stale on delivery: eight line counts were
read before that round's last edits landed, three test counts before the files
that hold them were split, and one test file was declared nowhere at all. A
blind measurement caught all twelve, which is the correct outcome and an
expensive way to learn it. Every number in section 3 below was taken after the
last edit of this round, by `wc -l` and by `pytest --collect-only`, and each one
that moved says what it used to say.

What is **carried forward and not re-run**, and is therefore a round-1 to
round-3 measurement rather than this round's: section 7's stopwatch and per-read
timings, section 5's money figures, and section 5's OpenAPI and `git diff` rows,
which were taken against a baseline that eight other wave-one pieces have since
written to and cannot be re-taken honestly from here. What was re-measured on
this tree: section 1's route table, read live from the running application's own
OpenAPI document, which publishes twelve paths under `/api/model`, fourteen
operations and four writes, plus `/api/impact`, and that is the thirteen paths
and fifteen operations section 4 is measured against; section 5's artifact
identity row; and section 7's gate counts, which still read 3, 5, 5 and 0.

Section 5.4 is the gap the last blind measurement left open, closed and measured
in a browser on this tree. The test count in section 3 moves with it, by the ten
guards that keep it closed.

The destination serves the model steward: which gate decided what, on how much
contrast, and what a rebuild would change. It did not exist before this round in
any form, so its Bar 3 row is "nothing regresses", with two named exceptions
that are duties rather than floors: the gate table must show every verdict the
calendar shows today, and no operator surface may keep showing them.

## 2. Payload shapes frozen

Four shapes carry the argument of the surface and are frozen here.

**A gate row.** Emitted by `/api/model/gates` and reused on the console header.

```
{id, model, family, label_en, label_he,
 state: active | tested_and_lost | no_contrast | not_measured,
 state_label_en, state_label_he, state_meaning_en, state_meaning_he,
 reason,
 basis: {statistic_en, statistic_he, value, unit, bar, bar_unit, bar_source,
         n, folds, fold_sd, measured_at, detail}}
```

`state` is derived, never labelled: a gate whose verdict is off and which
carries a measured figure was tested and lost; one with no figure could not run.
`bar` is read from the engine constant that applies it and `bar_source` names
that constant, so no threshold is asserted in the API layer.

**A blocked-register row.** Emitted by `/api/model/coverage`.

```
{gate_id, label_en, label_he, reason, condition_en, condition_he, source,
 earliest: {start, end, name_he, kind} | null,
 earliest_state: dated | unknown,
 evidence: {...}}
```

**A candidate row.** Emitted by `/api/model/candidates`.

```
{id, file, bytes, sha256, computed_at, purpose, subject_en, subject_he,
 gate_deltas: [{key, shipped, candidate, ...}],
 coefficient_deltas: {cells_compared, cells_moved, max_abs_delta,
                      max_abs_delta_cell, mean_delta, ...},
 money: {state: measured | not_measured | measuring | stale, ...},
 fingerprint}
```

**A decision record.** Emitted by `/api/model/decisions` and `/api/model/versions`.

```
{decision_id, recorded_at, actor, model_version_id, model_version_name,
 subject: current | candidate, candidate_id, decision: shipped | not_shipped,
 reason, release_note_he, release_note_en, money_direction,
 evidence: {gate_counts, gate_total, money_state, revenue_delta, scope, ...},
 adoption: {state, performed, reason_en, reason_he, measured_revenue_delta, scope}}
```

## 4. The wall, and the test wave zero could not write

C2 measured at the close of wave zero that `guard()` and `company_only()`
appeared on zero routes, that the two model routes took no request parameter at
all, and that no test could assert a refusal because there was no refusal to
assert. That is now closed on this surface:

- `MODEL_WALL = Wall(company_only=True)` is declared once in
  `model_console_api.py` and covers every route on the surface, including the
  two in their own files. Fourteen of the fifteen operations wear
  `@MODEL_WALL.guard()` and refuse. The fifteenth, `GET /api/impact`, consults
  the same gate in the handler through `MODEL_WALL.allows_read(request)` and
  answers instead of refusing, for the reason in the next paragraph.
- The refusal is the shipped constant `COMPANY_SURFACE_DETAIL`, not a new
  string, so the words the frontend shows before the click and the words the
  server sends cannot drift, and `session.js`'s frozen `WALLS` still covers it.
- `tests/test_p7_model_wall.py` enumerates the routes **from the running
  application's own route table** rather than from a list, so a route added to
  this surface later without the wall fails that file instead of shipping open.

**The measured behaviour, and the one deliberate 200.** The walled surface is
thirteen paths and fifteen operations: P7's own eleven paths and thirteen
operations, plus the two pre-existing reads the section 8.2 table assigns to it.
Measured on real resolved sessions through a live client against
`kairos_api.server.app`, a channel-affiliated operator is refused **fourteen of
the fifteen** with 403 and the Hebrew denial `התצוגה הזו שמורה לצוות החברה`.

The exception is `GET /api/impact`, and it is a decision rather than a gap. That
path answers **200** with exactly two keys and no measurement:
`{"state": "unavailable", "state_reason": "התצוגה הזו שמורה לצוות החברה"}`. The
frozen shell fetches it unconditionally for every account
(`src/shell/use-kairos-data.js`), and any non-200 among that batch sets
`partial`, which renders "Some data failed to load" on every operator page for
the whole session. So the wall closes the content and not a door the product
depends on. The tri-state is the refusal, and
`test_a_channel_account_gets_an_answer_from_the_answering_route` asserts the
body key by key, including that it never grows a third key. **A reader auditing
the affiliation wall should expect one 200 here and read it as the wall
holding, not as a breach.**

A company viewer reads all eleven GETs and is refused every write; an
administrator records a decision. Every body on the surface, refusing and
answering alike, carries zero hits of section 4.2's training lexicon, greped on
the wire across all fifteen operations.

Round 1 published this paragraph as "refused all thirteen operations with the
Hebrew denial". That sentence counted only P7's own operations and predated the
answering route, and it was false against the shipped tree until this revision.

## 5.4 The filter that opened a hole and contradicted its own count

The measurement that failed the round before this one, on the console's first
screen. The five state chips are the filter, so a chip is a number that opens the
rows behind it, which is the mechanic the reference gets right: the Open LLM
Leaderboard goes from 4576 of 4576 to 165 of 4576 on one press. Three things
were wrong at once here, and every one of them was a rendered consequence that
no assertion about the source could have seen.

- Pressing `0 טרם נמדד` rendered no rows, no gate groups and no sentence of any
  kind. The screen went from the chip legend straight to the next panel's
  heading. A number that promises to open rows opened a silent hole, which is
  section 3.6's dead end exactly.
- The panel subtitle read `13 מתוך 13` under all five chips, including the one
  that rendered three rows, because it was composed from the unfiltered array.
- The chips carried no `aria-pressed` and no `role`. Which one was active was
  carried by the CSS class `on` alone, while the console's own rail sets
  `aria-current="page"` correctly, so the surface was inconsistent with itself.

All three are closed in `console/GatesPanel.jsx`, and a fourth was closed with
them because the first two made it visible: the two gate families were hard
coded, so a gate in any third family would have vanished with no trace while its
chip went on counting it. The families are now derived from the rows on screen,
which is what makes "the chip count equals the rows rendered" an assertion that
can hold rather than a coincidence of today's data.

## 6. What this piece deliberately did not do

- **It did not wire the context switcher into the account menu.** Section 4.7
  puts it there and section 3.2 makes the console a different shell reached
  through it. Both `src/shell/side-rail.jsx` and `src/shell/workspace-router.jsx`
  froze at wave-zero close, so this is an escalation. What ships instead is a
  bridge inside `src/model/**`, documented at the head of `console-bridge.jsx`,
  which mounts its own root and renders the switcher with exactly the label
  section 4.7 specifies. Replacing it is a two-line change in the shell and a
  deletion here. **This is the piece's one open blocker and it is the lead's.**
  The address itself is real: `#Model` opens the console on a cold load and
  survives a reload, so the switcher's position is the only part still owed.
  The bridge is also mounted through a single import chain that ends in
  `src/rules/CalendarEventsModel.jsx`, which P5 owns. If that piece drops its
  import of `AudienceModelBlock`, this destination stops mounting. Nothing
  inside `src/model/**` can prevent that, which is a second reason the shell
  should carry the mount.
- **It did not run a training that overwrites a shipped artifact.** Both
  training scripts write only where `--output` points, and the console forces
  that path inside `models/releases/training_runs/<run id>/`. Overwriting
  `models/tv_break_coefficients.json` moves revenue in every plan run afterwards,
  which is an owner-approved act nobody proposed. Measured live on this round:
  a run started from the console finished in 8.1 s, wrote
  `models/releases/training_runs/tr-20260801T085605-07bae3/audience_model.json`
  with a digest of `aea3d854`, and left `models/audience_model.json` at
  `862cf829`, byte-identical to `git show HEAD`. Round 3 added that the run
  directory was removed afterwards so the store held only candidate
  measurements. That sentence is false on this tree and this round removes it
  rather than making it true, because deleting a directory a run record points
  at would leave the training log naming an artifact that is not there.
  `models/releases/` is untracked, so none of it is committed and the tree
  ships none of it. The working tree holds four run directories recorded in
  `training_runs.json`: three retention runs by the actor `critic` and one
  audience run by the actor `steward`, each holding exactly the one artifact its

- **It did not adopt a candidate.** A ship verdict is recorded with its measured

- **It did not carry the activation control.** The console mirrors the state and

- **It did not delete `src/model/ModelView.jsx`.** The piece that owns the Data

  coefficient and drift blocks are replaced by the console; its parameter ledger
