## 2. Payload shapes

### 2.1 `GET /api/uploads/status`

`{inputs: [...], model: {...}, summary: {...}, can_edit, can_edit_reason?}`.

Each input carries `kind, label_en, label_he, cadence, filename, path, exists,
rows, columns, columns_withheld, last_modified, valid, in_use, in_use_reason,
engine_reads, last_validation, warnings, size_bytes, model_input, state, remedy,
consequence, checks, stored_unread, stored_unread_total`.

- `columns` is the file's own header minus any name that carries a channel this
  operator does not own, and `columns_withheld` is how many that was. Measured
  before round four, with the operator channel `רשת 13`: the dayparts record
  carried three of them in the payload the browser and the assistant's own read
  tool both receive. The count is the disclosure and it is what keeps the
  arithmetic honest: the card adds the two together, so the number of columns it
  prints is the number the file really has. Validity is still judged on the full
  header, so withholding a name can never make a file look complete.

- `last_validation` carries the keys it always did, `dataset, filename,
  checked_at, accepted, is_valid, errors, warnings, findings, rows_loaded`, and
  **every sentence in it is rendered at this read rather than replayed from
  disk**, which is round seven's correction. Measured before it, with the
  operator channel `עכשיו 14`: a dayparts refusal stored earlier under `רשת 13`
  came back three times, in `errors[0]`, `findings[0].message` and
  `findings[0].message_he`, and the card printed it inside its own
  `נבדק לאחרונה` block as this account's own channel. A report stored before
  this format carries a sentence nothing can re-author, so one that names a
  channel this account may not read is replaced, in both languages, by a notice
  saying so and naming the act that supplies the reason again, with the code and
  the severity kept.
- `state` is one of six and never a seventh: `in_use`, `shadowed`, `not_read`,
  `empty`, `invalid`, `missing`. `remedy` is a `{code, en, he}` record and every
  state has one, so a badge never lands without the thing to do about it.
- **The state is derived from content and from siblings, not from the read path
  alone**, which round one got wrong in two measured ways. A file the engine
  reads that carries a header and zero data rows is `empty`, never `in_use` with
  nothing to do, because no figure anywhere can come from it. And a kind that has
  other files on disk the engine does not read names them in `stored_unread`,
  each `{filename, path, rows, size_bytes, last_modified, arrived_after_live,
  reason}` with `reason` a `{code, en, he}` record; when one of them arrived
  after the file being read, the kind is `shadowed`, because the operator's own
  most recent act is not what any number rests on. The list is capped at six and
  `stored_unread_total` is not, so a cap hides no count.
- `in_use` stays the read verdict on the file this record NAMES, and is not
  re-pointed at the sibling. Measured reason: it is paired with `consequence`,
  and an `in_use` false on the daily kind would print "nothing reads this file,
  so uploading changes no number" over an input where a newer-dated upload
  genuinely does change every number. The sibling's own verdict travels with the
  sibling, and it also enters `warnings`, so a reader that renders warnings and
  nothing else stops short of a bare green badge.
- `consequence` is one of four here, `replaces_live_input`,
  `changes_model_basis`, `stored_not_read` and `replaces_only_a_later_day`,
  derived from the real read paths and from whether the model version was
  measured on the file this kind is read from. This one is about the KIND,
  because the status has no candidate file in front of it. The fifth code
  belongs to the door and is at 2.2.
- **`remedy` and `consequence` are one answer and are derived together**, which
  is round eight's correction, and the fourth code above is what it needed.
  Measured before it, on the shipped card: a shadowed daily input printed the
  remedy `הסירו את הקובץ שהמנוע קורא קודם, או המשיכו להעלות כאן והתוכנית לא תשתנה.`
  and, one line below it, the consequence
  `זהו הקלט החי. העלאה מחליפה את מה שהתוכנית מחושבת ממנו.` The first says an
  upload here changes nothing and the second says it replaces what the plan is
  computed from, and neither named the airing date that decides between them.
  Both were reachable at once because `shadowed` is two different pieces of
  news: a kind another file is read INSTEAD of, where nothing uploaded is ever
  read until that file goes, and a kind whose own file is read and whose last
  upload lost the resolver, where the next one is read or not read by the day
  its name carries. The second now carries its own remedy code,
  `shadowed_by_a_later_day`, and the conditional consequence, both naming the
  file that won. `in_use` and `state` keep the meanings 2.1 already fixed:
  nothing was re-pointed, and a card that was not in this state prints exactly
  the words it printed before.
- `checks` is what the door actually runs: `{required_columns, loader, contract,
  checked_en, checked_he, cannot_verify: [{code, en, he}]}`. `loader` and
  `contract` are the real dotted names, so a rename that is not reflected there
  is visible.
- `model` is `{available, version, trained_at, status, changed_sources,
  measured_on, note_en, note_he}` with `status` the engine's own tri-state
  `fresh` / `stale` / `unknown` from `kairos/model/freshness.py`, which is read
  and never written. No gate verdict, coefficient value, coverage figure or
  p-value crosses.

8. `also_read` is what the engine reads that the audit never named. `stored` is

and on no screen in the product, because the audit lists what is read and
`_newest_daily` reads exactly one file out of a directory.

## 6. Raised, not fixed

1. **A single worker serves twelve boot fetches, and that is what a cold page
   load costs.** The endpoint's own work is 94 ms with every cache cold and
   17 ms warm, measured out of process against the shipped files: the model
   version costs 10 ms and the seven row counts cost 84 ms, of which the
   15.7 MB spots file is 64 ms. In a browser, the same call inside a cold page
   load takes 1,077 ms because it queues behind `break-operations` at 1,323 ms
   and `reports` at 1,125 ms, all twelve issued at once against one uvicorn
   worker. The page reaches seven cards in 1.504 s cold and 0.394 s warm.
   Closing the rest is the concurrency work section 6 of the specification
   names, and it is nobody's row in wave one.

   **Round five corrects this entry's own number, because it did not
   reproduce.** It read "90 ms on its first ever call", which is the endpoint's
   work and is what a reader takes for the wall clock of the first request. Timed
   with `curl` against three freshly started workers it is 2.202 s, 2.794 s and
   3.349 s, then 42 ms to 640 ms on the calls after it, at load average 9.95 with
   eight builders on the machine. The gap is not the endpoint: `uploads_status`
   imports `kairos.model.measure` and `kairos.model.freshness` inside the
   functions that use them, so the worker pays for that import chain on the first
   request rather than at boot, and the chain measures 7.564 s in a cold
   interpreter. Hoisting the imports would move the bill to every server start,
   including the ones that never open this endpoint, which is a worse trade than
   the one in place, so this is measured and left rather than traded blind. What
   is true either way: warm, the endpoint answers in 4 ms to 11 ms on a quiet
   machine and meets JS-12's sub-second bar; on a worker's first ever request it
   does not, and the reason is an import and not a read.
2. **The seventeen navigation entries are still seventeen.** JS-11's floor is
   "17 entries become 5". `shell/nav.js` and `shell/workspace-router.jsx` froze
   at wave-zero close and no wave-one row owns them, so the consolidation has no
   owner. Sources already behaves as one destination with three views behind two
   of the seventeen entries, `Data` and `Reports`, and each entry opens the view
   it names.
3. **The refusal a viewer reads on the deployed server is not this surface's
   sentence.** `auth.enforce_request` refuses every mutating method to a viewer
   role before any route runs, and its detail is `A viewer session is
   read-only.` in English. Measured on the whole app with a real viewer cookie:
   `GET /api/uploads/status` says `can_edit` false with
   `לחשבון צפייה אין הרשאת עריכה`, and `POST /api/uploads/daily` answers 403
   with the English line, so the words before the click and the words after it
   differ on a Hebrew-first surface. The route's own wall now answers the same
   sentence the status prints, which is the half in this piece's hands.
