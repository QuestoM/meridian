# W0-1 Router seams: the published contract

Frozen on delivery. This is the section 8.8 publication for W0-1: the endpoints
it owns, the payload shapes it emits, the files from section 8.2 it writes, and
the helper module names it creates. It also carries the two things the third
critic asked for by name: the complete current-route to destination-module map,
and the full public signatures of `kairos_api/plan_read.py`, so a later piece
that needs one more accessor can read the signature here instead of stalling on
a closed wave.

Nothing in this piece changes behaviour. The bar is the live OpenAPI surface,
byte identical after the split: 90 paths, 113 operations, 56 write operations,
measured in process on the current code before any edit.

## 4. The four split modules after the split

None of the four is deleted, because 14 modules and 20 test files import names
from them and every one of those files is frozen to W0-1. Each keeps its name
and re-exports every name it defined before, against the same objects, so every
`lru_cache`, the frontier lock and the frontier state dict stay single instances.

| Module | After | Owner |
|---|---|---|
| `kairos_api/dashboard_api.py` | Re-export layer, 48 names, no routes | W0-1, frozen at wave-zero close |
| `kairos_api/insights_api.py` | Re-export layer, 23 names, no routes | W0-1, frozen at wave-zero close |
| `kairos_api/catalog_api.py` | Re-export layer, 26 names, no routes | W0-1, frozen at wave-zero close |
| `kairos_api/version_store.py` | The version store itself, 41 store names, plus the 14 route-layer names resolved lazily from `history_api` | W0-1, frozen at wave-zero close |

**A re-exported name stays substitutable, not merely resolvable.** Three frozen
tests measure a cache key by substituting `SETTINGS_PATH`, `DATA_DIR`, `ROOT`,
`OUTPUT_DIR` or a loader on one of these modules and asserting that touching the
file invalidates the cache; a fourth substitutes a builder for one that raises
and asserts the cold overview never calls it. A plain re-export would resolve
those names and reach nothing, turning four real measurements into silent
no-ops. `kairos_api/split_compat.py` therefore mirrors a write to a re-exported
name into the module that now reads it, by the same name and by the same object,
so a name that lost its leading underscore on the move is still reached. Reads
are untouched.

`version_store.py` keeps `router` because three fixtures in
`tests/test_uploads_versions_security.py` mount it into their own app. The name
resolves through a module `__getattr__` to `history_api.router`, so the object is
the one P8 owns and there is no import cycle.

## 5. `kairos_api/server.py` after wave 0

Everything above the marker is unchanged, line for line, including the twenty
existing `include_router` calls and the four imports of the split modules, which
still resolve because the four modules still export every name.

The marked region is added after the final existing mount and before the cache
warm-up and the static mount, so an appended stanza can never be shadowed by the
`StaticFiles` mount at `/`, which is the risk section 8.2 names. It holds one
two-line stanza per router W0-1 creates, thirteen of them.

`history_api.py` is the one exception and it is deliberate: it is already mounted
by the existing `version_store` stanza above the marker, which now resolves to
P8's router. Mounting it again in the region would define all five version paths
twice. The region says so where a later builder will read it.

## 7. Raised, not fixed

Three things this piece found and deliberately did not touch, each with the
evidence a later piece needs.

1. **The operator channel picker offers three channels the operator does not
   own.** `tv-break-dashboard/src/TVBreakDashboard.jsx:5214` renders
   `OperatorChannelPanel` from `parameters.available_channels`, which is
   `['כאן 11', 'עכשיו 14', 'קשת 12', 'רשת 13']` measured live, while
   `operator_channel` is `רשת 13`. The picker has to name a channel to select it,
   so this is a competitor-boundary question, not an obvious defect: whether a
   channel-affiliated account may see the other three names at all is W0-4's
   wall and C1's sweep. It is not W0-1's to answer and the file is not W0-1's to
   write.
2. **No test-change request. Four frozen probes were about to break and the
   compatibility layer was made to carry them instead.** Three tests in
   `tests/test_qa2_api_seams.py` substitute `SETTINGS_PATH`, `ROOT`, `DATA_DIR`,
   `OUTPUT_DIR` and the loaders on `dashboard_api` or `catalog_api` to prove a
   cache key invalidates; they went red on the first split and are green again
   through `split_compat.py`. Two more, the cold-overview probe in the same file
   and `tests/test_qa_known_bugs_20260706.py::test_compliance_fallback_survives_an_empty_schedule`,
   would have passed while asserting nothing; the same mirror keeps them
   meaningful, measured: substituting the geometry raises inside
   `build_compliance`, and the cold overview builder with substituted loaders
   returns in 0.01 s rather than rebuilding the plan. The same two assertions are
   also carried against the new modules in `tests/test_w0_1_module_seams.py`, so
   they survive if a later piece retires the mirror.
3. **`/api/schedule` still embeds the day board.** `GET /api/schedule` returns
   `break_operations`, the whole break board, inside the week payload, which is
   why `build_break_operations` has to sit in the frozen read layer instead of in
   P3's module. Bar 3 forbids changing it in this wave. P2 and P3 may want to
   retire the embedded copy together once both surfaces exist.
