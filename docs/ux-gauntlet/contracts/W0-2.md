## 3. The helper collision the frozen shell would otherwise ship, ruled

The critic is right that nothing on disk said which module a wave-1 page must
import, and `src/shell/**` freezes at wave-zero close, so an ambiguity left here
is permanent. This section is the ruling, and section 3.4 is what enforces it.

### 3.1 What collides: the complete census, measured

The shell exports 104 names. Eleven of them come from two modules rather than
one. The critic named nine; the census finds two more, `API_BASE` and
`normalizeRows`, so the ruling below covers all eleven.

| Name | Exported from | Bodies |
|---|---|---|
| `API_BASE` | `api.js`, `surface-helpers.js` | identical |
| `finiteNumber` | `format.jsx`, `surface-helpers.js` | identical, 206 bytes |
| `formatCurrency` | `format.jsx`, `surface-helpers.js` | identical, 472 bytes |
| `formatCurrencyAxis` | `format.jsx`, `surface-helpers.js` | identical, 393 bytes |
| `formatMinutes` | `format.jsx`, `surface-helpers.js` | identical, 289 bytes |
| `formatNumber` | `format.jsx`, `surface-helpers.js` | identical, 477 bytes |
| `formatPercent` | `format.jsx`, `surface-helpers.js` | identical, 156 bytes |
| `normalizeRows` | `plan-model.js`, `surface-helpers.js` | identical |
| `pageText` | `format.jsx`, `surface-helpers.js` | identical, 81 bytes |
| `daypartLabel` | `labels.js`, `surface-helpers.js` | **different**, disjoint keys |
| `programTypeLabel` | `labels.js`, `surface-helpers.js` | **different** bodies, same 18-key Hebrew table |

Nine of the eleven are byte identical, comments included, so the import choice
cannot change what renders. Two are real forks:

- `daypartLabel` answers two disjoint key sets,
  `{morning, noon, evening, prime, night, unclassified}` against
  `{Morning, Daytime, Access, Primetime, Late night}`.
- `programTypeLabel` holds the same Hebrew table on both sides, 18 keys, equal
  key for key and value for value. The bodies differ only in input handling:
  `surface-helpers` coerces and trims (`String(value ?? '').trim()`), `labels`
  does not. On a trimmed non-empty string, which is what every call site passes,
  the two return the same text.

None of this was created by the split. At 5a80a709 nine of the eleven were
defined twice already, once inside `TVBreakDashboard.jsx` (lines 619 to 873) and
once in `surface-helpers.js`. The split gave the monolith's copies a module home,
which is what turns an invisible duplication into an import choice.

| Name | Canonical module | Rule for a wave-1 author |
|---|---|---|
| `finiteNumber`, `formatCurrency`, `formatCurrencyAxis`, `formatMinutes`, `formatNumber`, `formatPercent`, `pageText` | `shell/format.jsx` | Import from `format.jsx` in new code. The `surface-helpers.js` copies are byte identical and stay valid, so no existing import has to move |
| `API_BASE` and the `fetchJson` wrapper around it | `shell/api.js` | Import from `api.js` in new code, same reason |
| `normalizeRows` | `shell/plan-model.js` | Import from `plan-model.js` in new code, same reason |

| `daypartLabel` for a key that arrived from the engine | `shell/surface-helpers.js` | Lowercase engine keys, the taxonomy in `kairos/data/dayparts.py`, plus the yield endpoint's `unclassified` |

and `plan/week/PlanningCanvas.jsx`. Every one of the five is on the right side of
the ruling today, measured.

### 3.3 Why `daypartLabel` is not merged into one function in this wave

Because merging would change what an operator reads, which Bar 3 forbids here,
and because the fix belongs to a piece that owns the surfaces.

The two key spaces are not two spellings of one taxonomy by accident. They are
two vocabularies over the same five hour buckets:

| Hours | Engine key | Engine Hebrew | Client key | Client Hebrew |
|---|---|---|---|---|
| 06 to 12 | `morning` | בוקר | `Morning` | בוקר |
| 12 to 17 | `noon` | צהריים | `Daytime` | יום |
| 17 to 20 | `evening` | ערב | `Access` | לפני פריים |
| 20 to 23 | `prime` | פריים טיים | `Primetime` | פריים טיים |
| 23 to 06 | `night` | לילה | `Late night` | לילה |

The boundaries agree exactly, measured against `daypart_for_hour` for all 24
hours and against `daypartForTime` in `shell/plan-model.js`. Two of the five
Hebrew labels disagree, so collapsing the tables would move visible text on the
week surfaces. That is raised in section 4 point 2, not fixed here.

The failure mode of importing the wrong one is measurable and silent: each table
passes an unknown key through verbatim, so a page that asks `surface-helpers` for
`Primetime` renders the English word inside a Hebrew surface, and a page that
asks `labels` for `prime` renders `prime`. Four of the five client keys and five
of the six engine keys behave that way.

### 3.4 What holds the ruling after the shell freezes

Three tests in `tests/test_w0_2_shell_seams.py`, so the ruling is machine
checked rather than documented:

- `test_the_two_shell_daypart_helpers_serve_disjoint_vocabularies` reads the

  neither table covers the other's.
- `test_every_duplicated_shell_export_is_identical_or_a_declared_fork` recomputes

- `test_the_two_shell_program_type_tables_are_the_same_table` asserts both
  Hebrew tables hold the same 18 pairs.

## 4. Raised, not fixed

1. **`tv-break-dashboard/scripts/verify-dashboard-render.mjs` is a blocker, and

   the product renamed to `DataPage` before this wave, all 5 required style
   fragments are still in `shell/styles.css`, and all four banned native controls
   appear somewhere under `src/`, so a naive tree-wide glob would fail that check
   even though it was only ever scoped to the monolith.
2. **Two Hebrew daypart labels disagree with the engine's own vocabulary.** The
   client-side grid renders `Daytime` as יום where the engine taxonomy says
   צהריים, and `Access` as לפני פריים where the engine says ערב. Same hours, two

   and `clients/agencies-helpers.js` also export it, with a body identical to the

   tree and are P4's to retire. `test_the_repointed_page_text_helper_is_the_same_function`
