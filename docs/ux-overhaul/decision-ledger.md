# UX overhaul decision ledger

Decisions made during the autonomous overhaul, with the alternative rejected and the implementation consequence kept visible. Decisions D-01–D-20 are dated 15 August 2026; D-21–D-25 record the final production calibration on 16 August 2026.

| ID | Decision | Alternatives considered | Why this decision | Implementation evidence / consequence |
| --- | --- | --- | --- | --- |
| D-01 | Adopt Studio Ledger as the visual and interaction direction | Signal Room; Signal Paper | It is the only direction that makes broadcast timing, commercial records, and governance feel like one instrument without forcing every surface into a dark control-room metaphor or generic enterprise blue | [`phase-2-direction.md`](./phase-2-direction.md), [`tokens.css`](../../tv-break-dashboard/src/tokens.css), Studio feature sheets |
| D-02 | Replace fifteen global entrances with seven durable domains | Preserve the old rail; organize by backend module | Operators think in jobs and consequence, not implementation modules. The old rail duplicated workspaces and hid the entity/time hierarchy | [`shell/nav.js`](../../tv-break-dashboard/src/shell/nav.js) defines Today, Plan, Broadcast, Commercial, Sources, Governance, History; old hashes remain aliases |
| D-03 | Keep Mabat as a persistent contextual dock | Full-page Assistant route; modal assistant | A dock retains task context and conversation continuity without competing with primary navigation | [`kai/AssistantDock.jsx`](../../tv-break-dashboard/src/kai/AssistantDock.jsx); `#Assistant` is normalized to a workspace plus open dock |
| D-04 | Place the company Model under Governance but give it an unmistakable company shell | Second React root overlay; ordinary operator page | Model stewardship is governance, but the company/channel boundary must remain obvious and permission-gated | `ModelConsole` is lazy-loaded from [`TVBreakDashboard.jsx`](../../tv-break-dashboard/src/shell/TVBreakDashboard.jsx); duplicate mount entries are quarantined outside the live import graph |
| D-05 | Make route state scoped, shareable, and Back-safe | Component-only state; `replaceState` for all navigation; allow query accumulation | Plan steps, selected entities, source filters, and Model sections are task state. Back/Forward must restore them, and unrelated domains must not leak parameters | [`shell/nav.js`](../../tv-break-dashboard/src/shell/nav.js) owns parameter domains and validation; feature navigations use `pushState`; normalization alone uses `replaceState` |
| D-06 | Mount and fetch only the active route/panel | Render all panels hidden; one monolithic initial bundle | Hidden Plan/DataGrid/Model work was contributing DOM, requests, warnings, and initial bundle cost | [`shell/workspace-router.jsx`](../../tv-break-dashboard/src/shell/workspace-router.jsx) uses route-level `React.lazy`; `PlanWeek`, Today, Sources, Rules, Commercial, History, Break Library, and Model mount active panels only |
| D-07 | Consolidate the weekly loop into one six-step Plan workspace | Keep Optimizer, Schedule, Inventory, and Forecasts as separate products | Objective, run, compare, publish, supply, and board are one weekly decision loop over the same data | [`plan/week/PlanWeek.jsx`](../../tv-break-dashboard/src/plan/week/PlanWeek.jsx); four old entry modules remain zero-bundle compatibility shims |
| D-08 | Split Broadcast by level of work while keeping direct drill paths | Keep day editor, override composer, pods, day table, and ranked library stacked on one page | Timeline placement, traffic-pod assembly, library analysis, and manual decisions are related but distinct conceptual tasks | Broadcast context routes directly to Day, Pods, Library, Decisions; [`BreakLibraryPage.jsx`](../../tv-break-dashboard/src/plan/break/BreakLibraryPage.jsx) mounts one local view at a time |
| D-09 | Use list/detail and progressive reveal for commercial and operational volume | Render every record and action at once; paginate without stable context | The baseline Campaigns and Pacing pages were dominated by repeated actions and multi-thousand-pixel documents. Stable windows keep totals and selection legible | 12 campaign rows, 16 pacing rows, 18 agency/advertiser rows, 20 break rows, and 12 override/decision rows are revealed in increments |
| D-10 | Turn onboarding into a four-step, full-height workflow | Keep the long one-submit modal; split it into unrelated transactions | Agency, client, campaign terms, and flights are one transaction, but not one undifferentiated form | [`clients/OnboardClientFlow.jsx`](../../tv-break-dashboard/src/clients/OnboardClientFlow.jsx) implements Identity, Commercial terms, Flights, Review with focus containment and background inerting |
| D-11 | Set 44px as the primary control/action minimum and 48px as the compact row | Preserve 28–46px mixed controls; enlarge only touch surfaces | High-frequency, high-stakes controls must not demand precision aiming; a single target law also improves keyboard focus visibility | Tokens, MUI component overrides, Studio primitives, day/break/plan/commercial feature layers |
| D-12 | Use local Noto Sans Hebrew Variable for Hebrew and IBM Plex Sans/Mono for Latin, figures, and identifiers | Keep IBM Hebrew as the primary face; use remote font CDN; let Noto supply Latin too | The user's reference was specifically about Hebrew typography. A Hebrew-only Noto subset improves Hebrew rhythm while IBM retains the established operational numeral and Latin voice; local assets remove runtime dependency | Hebrew-only Noto variable WOFF2, IBM Plex packages, three critical preloads in [`index.jsx`](../../tv-break-dashboard/src/index.jsx) |
| D-13 | Retain Lucide as the only live icon source | Draw a partial custom set; introduce another library | Lucide was already the sole live source and replacing 97+ glyph needs a complete optically reviewed set, not a mixed transition | `lucide-react@1.22.0`; canonical actions normalize 20px/1.75px; direct legacy imports remain a migration boundary |
| D-14 | Use native modal mechanics for canonical Dialog/Sheet and explicit focus/inert policies for complex inspectors/workflows | Visual overlays with `role` only; nested modal stacks | Names, initial focus, Escape, restoration, and background isolation are behavior, not styling | [`shell/primitives.jsx`](../../tv-break-dashboard/src/shell/primitives.jsx), Plan command palette, onboarding workflow, Schedule and Break inspectors |
| D-15 | Preserve uncertainty and provenance instead of filling gaps | Show zero/default values; visually smooth traffic/plan date mismatch | Modeled gross, delivered money, missing source days, and unavailable services have different operational meanings. Invented completeness would be dangerous | Today partial/error states, Sources truth states, Pacing unknown days, Break inspector basis, History refused/unreachable states |
| D-16 | Prohibit one-sided decoration and pure white/black | Keep concept A's selected-edge stripe; use borders as the default separator | Hierarchy should survive without ornamental crutches and the selected direction needs a coherent material system | Production styles use complete selected surfaces, spacing, and sparse boundaries; concept stripe was not implemented |
| D-17 | Replace phone/tablet adaptation with a complete localized desktop gate | Reflow the dense console; leave the broken partial mobile shell | The user explicitly accepted desktop-only operation. A truthful gate is safer than a compressed planning surface and avoids hidden auth/data work | [`shell/desktop-gate.jsx`](../../tv-break-dashboard/src/shell/desktop-gate.jsx) branches above session/data; Hebrew/English copy states the 1200px requirement |
| D-18 | Protect desktop zoom from a width-only rejection | Strict `<1200px` media query | A 200–400% zoomed desktop can report a narrow CSS viewport; width alone would punish low-vision users | The gate combines CSS width with fine/coarse pointer, physical available width, outer width, and zoom-ratio evidence; this remains an explicit heuristic in the assumption ledger |
| D-19 | Keep compatibility source only when capability/tests still depend on its public shape, and keep it out of production chunks | Delete every old filename immediately; continue importing wrappers | Preserving capability and integration contracts is more important than cosmetic source-tree purity; route-level direct imports keep the quarantined modules at zero bundle cost | See [`deprecation-ledger.md`](./deprecation-ledger.md) for the current nine-module, 776-line compatibility set and removal conditions |
| D-20 | Replace the initial dark treatment with warm cream, near-black ink/chrome, and mineral sage | Keep the dark control-room palette; reduce to literal black/white | The user rejected the dark colours and asked for cream with a lightly anthroposophic material quality, or sharp monochrome. Warm material surfaces plus near-black authority preserve operational confidence without theatrical decoration | [`tokens.css`](../../tv-break-dashboard/src/tokens.css), [`shell/theme.js`](../../tv-break-dashboard/src/shell/theme.js), current cream gallery |
| D-21 | Ship one transparent, two-path frame-splice master mark | Generated bow-tie/gradient, equalizer, slab-letter `K`, or a raster logo with a plate | The generated directions read as generic media software or a literal initial. An institutional product mark must survive rail, loading, login, and gate contexts without changing asset or relying on a background | [`shell/kairos-icons.jsx`](../../tv-break-dashboard/src/shell/kairos-icons.jsx) contains two filled `currentColor` paths on one 32px grid, separated by an off-axis negative-space splice; no generated bitmap ships |
| D-22 | Collapse the shell header to one 57px band, including Broadcast and Governance local navigation | Keep the tall primary row plus a second local-navigation row; hide local navigation behind a menu | Orientation, local choice, live state, and utilities belong to one persistent instrument frame. A second row spent vertical space and made destinations feel like separate products | [`shell/studio-shell.css`](../../tv-break-dashboard/src/shell/studio-shell.css) provides the 56px content row and 1px boundary; [`shell/shell-continuity.css`](../../tv-break-dashboard/src/shell/shell-continuity.css) places bounded local navigation in the middle column without wrapping or shrinking targets |
| D-23 | Use causal workspace-only continuity for page and addressable-tab changes | Hard cuts everywhere; animate the whole shell; decorative crossfades unrelated to navigation | The rail and header are spatial memory. Only the changed workspace should acknowledge the operator's action, and semantic focus must arrive after the visual boundary | [`shell/workspace-continuity.js`](../../tv-break-dashboard/src/shell/workspace-continuity.js) feature-detects View Transitions, commits atomically, falls back to the same small workspace cue, and preserves focus; reduced motion removes animation without removing navigation behavior |
| D-24 | Make the workspace and card own their padding, then measure edge contacts in the final evidence harness | Let every page/child invent an inset; add arbitrary padding where a screenshot looks empty | The visible gaps were ownership defects: double route gutters in some places and flush card/table/status content in others. One owner makes omission safe and named bleed explicit | [`shell/studio-shell.css`](../../tv-break-dashboard/src/shell/studio-shell.css), [`shell/styles-workspaces.css`](../../tv-break-dashboard/src/shell/styles-workspaces.css), and [`shell/card.css`](../../tv-break-dashboard/src/shell/card.css); the capture harness records main/route padding and under-12px edge contacts without pre-claiming its final matrix result |
| D-25 | Move owned feature seams through the public `src/studio` API incrementally | Claim the primitives are adopted because they exist; force an unsafe flag-day rewrite | A public API is real only when application modules consume it, but capability and regression evidence still govern migration speed | Fourteen application modules now import Button, Dialog, DataTable, PageHeader, Metric, StatusBadge, or compatibility Card composition from `src/studio`; direct primitives/MUI consumers remain named debt |
| D-26 | Preserve exact manual Plan arrangements as browser-local drafts beside an immutable optimizer baseline | Treat every edit as an immediate server write; invent server-side version persistence that does not exist; allow the first re-plan to erase the original comparison | Operators need to explore, name, compare, adopt and discard arrangements before changing the official plan. Local identity is exact and stale-aware; the separate reviewed re-plan remains the only server mutation | [`plan/week/LocalPlanVariants.jsx`](../../tv-break-dashboard/src/plan/week/LocalPlanVariants.jsx), [`plan/week/local-plan-variants.js`](../../tv-break-dashboard/src/plan/week/local-plan-variants.js), and [`plan/day/day-board-variant-draft.js`](../../tv-break-dashboard/src/plan/day/day-board-variant-draft.js) |
