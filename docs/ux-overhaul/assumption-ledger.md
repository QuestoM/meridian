# UX overhaul assumption ledger

These are the assumptions the implementation relies on. An assumption is not promoted to a verified fact merely because the interface was designed around it. Each row names the evidence, current validation level, and the behavior if it proves false.

| ID | Assumption | Basis | Current status | If false / next validation |
| --- | --- | --- | --- | --- |
| A-01 | Kairos is an operator console for Israeli commercial television, not a generic analytics dashboard | Domain data, route/state map, pricing/licence/pod/pacing workflows | Strong product evidence; documented in [`product-model.md`](./product-model.md) | Revisit IA and language with named operators before broadening the product category |
| A-02 | The weekly plan, broadcast-day/pod control, and commercial delivery are the three product-carrying jobs | Frequency/stakes analysis and baseline journeys | Strong code/data evidence; not validated with external user research in this overhaul | Compare with production telemetry/interviews; change domain priority without changing capability |
| A-03 | Mobile and tablet operation is out of scope; a desktop gate is the desired product behavior | Explicit user instruction during the overhaul | Approved product decision | If field operation becomes required, commission a distinct task-specific mobile product rather than shrinking the desktop console |
| A-04 | A supported working canvas begins at 1200 CSS px, with an 88px compact rail until 1400px | Density of timeline, tables, inspectors, and selected direction | Implemented constant; browser QA belongs in the separate validation pass | Re-measure with target hardware and operators; change the named token/constant, copy, and acceptance probes together |
| A-05 | A zoomed wide desktop should bypass the gate even when its CSS viewport is below 1200px | Accessibility acceptance criterion; browsers expose no standard zoom API | Implemented heuristic, not a browser guarantee | Validate on Chrome/Safari/Firefox at 200–400%. Adjust the combined signals; never fall back to width-only gating |
| A-06 | Fine hover pointer + no coarse primary pointer + available/outer width ≥1200 + outer/layout ratio ≥1.12 is sufficient evidence of a zoomed desktop | Available web-platform signals in [`desktop-gate.jsx`](../../tv-break-dashboard/src/shell/desktop-gate.jsx) | Inference only | Test touch laptops, external monitors, split-screen, display scaling, browser sidebars, and remote desktops; record false positives/negatives |
| A-07 | Hebrew is the primary operational language and English remains a fully supported control locale | Existing localization, RTL primitives, user/data context | Implemented in shell and gate; final locale QA not claimed here | Review both locales screen-by-screen, including accessible names, MUI portal direction, numerals, and mixed-script entities |
| A-08 | Job selects the first useful surface; role and affiliation govern authority | Thirteen jobs and three authority roles in the current session/domain model | Implemented in several landing/permission decisions, but not supported by user research in this run | Validate role/job matrix with product owners; keep server permission checks authoritative |
| A-09 | Company Model access is valid only for open access or `affiliation === "company"` | Current frontend session contract and backend route refusals | Implemented in shell routing/menu; backend remains final authority | Test channel/company/admin/viewer matrices against a configured auth environment |
| A-10 | Existing API and flat-file contracts are the capability authority; the overhaul should not change backend meaning | User required capability/data preservation; Phase 3 is frontend-focused | Followed; UI tolerates older/missing endpoints in many surfaces | Contract-test each read/write path. Missing endpoints must continue to render refused/unreachable/partial, never invented success |
| A-11 | Unknown, missing, refused, stale, modeled, observed, and zero are distinct domain states | Traffic gaps, As Run absence, source status, model gates, history outcomes | Strong domain evidence and encoded UI copy | Treat any payload ambiguity as a contract issue; do not collapse it in presentation |
| A-12 | Legacy hashes may be bookmarked or linked externally | Fifteen previously visible entrances and compatibility routes | Conservatively preserved, not measured | Collect route usage after release. Remove an alias only with a redirect window and explicit migration note |
| A-13 | Query parameters are private to one domain except deliberate handoffs | Baseline leakage made addresses ambiguous | Implemented ownership map in `shell/nav.js` | Add route tests for every valid/invalid parameter and all Back/Forward transitions |
| A-14 | Progressive reveal is preferable to immediate virtualization for current list sizes | Need to reduce DOM/action density while keeping totals, focus, and simple record expansion | Implemented fixed windows; performance effect not yet measured in this document | Profile production-size lists. Move to keyed virtualization only if reveal windows still miss latency/memory targets |
| A-15 | Local Fontsource packages are acceptable production dependencies | Offline/runtime reliability and OFL-1.1 package metadata | Installed and production build emits local assets | Legal/brand owner should retain licence notices and verify redistribution policy as part of release governance |
| A-16 | Lucide can remain the single icon family for this release | It was already the sole live source; a partial custom replacement would introduce inconsistency | Verified by source import scan | Audit optical consistency of the 117 direct imports; replace only through a complete versioned wrapper/set |
| A-17 | The concept renders are art-direction evidence, not product assets or screenshots | They were generated before implementation from normalized content | Explicitly documented and not imported by runtime code | Never place them in before/after product evidence; use browser captures for implementation proof |
| A-18 | Open-access mode is an intentional supported local/deployment state, not an authentication success | Existing session boundary and copy | Preserved and labeled honestly | Validate configured authentication separately; do not infer permission behavior from open-access QA |
| A-19 | The audit's read-only plan environment is appropriate for exploration but cannot prove production write flows | Baseline ran with `KAIROS_PLAN_READONLY=1` and assistant credentials blank | Known limitation | Run destructive/write-flow QA only against an isolated data copy with explicit authorization, then document outcomes |
| A-20 | The current traffic dates and saved-plan dates may legitimately differ | Baseline evidence showed traffic on 27 April 2025 and plan data in November 2024 | Preserved as an honest mismatch | Production data owners should define the authoritative same-day reconciliation source; UI must not imply overlap until it exists |

## Assumptions deliberately not made

- A missing API row is not assumed to be zero.
- A demo-seeded campaign is not assumed to be an operator booking.
- Modeled revenue is not assumed to be billed revenue.
- A visually hidden or unmounted control is not assumed to preserve capability; capability is traced to a reachable replacement or logged as deprecated.
- A successful production build is not assumed to prove browser behavior, write safety, accessibility, or visual quality. Those require separate evidence.
